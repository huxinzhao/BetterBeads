## 项目约定

### 已确定的内容

1. Mod 名称为“更好的拼豆”，拼豆台配方由罗宾出售。
2. 支持将不同物品加工为豆子；某种原料第一次成功加工时解锁对应色卡。
3. 材质与颜色分别保存；颜色改变不影响材质用途、重量、硬度和特殊效果。
4. 玩家自由拼图，并制作家具、雕像、武器和服装。
5. 武器由铱豆、金属豆、宝石豆及其比例形成不同属性。
6. 羊毛豆做服装，石豆做雕像，木头豆做家具。
7. 拼豆台保存玩家图纸，支持自由添加、修改、复制、改名、删除和再次制作。
8. 支持读取物品 sprite 作为可编辑的拼豆原型。
9. 作者负责拼豆台、熨斗、豆子、正式界面素材和服装版型；Codex 负责布局、交互、配置及程序。
10. Codex 只检查代码，所有游戏内实测由作者完成。
11. 拼豆 UI 在编辑器阶段完整设计，不等到最终换美术时才决定布局。

### 材质用途表

原料来源为建议初始配置，最终产量和数值配置化，不把举例直接当成最终平衡值。

| 材质 | 建议来源 | 允许用途 | 必须保留的信息 |
| --- | --- | --- | --- |
| 铱豆 | 配置中的铱矿石／铱锭 | 剑、匕首、锤等武器 | 独立材质 ID、重量、硬度、可选效果 |
| 金属豆 | 配置中的铜／铁／金矿石或金属锭 | 武器 | 铜、铁、金等子类分别配置 |
| 宝石豆 | 配置中的红宝石、海蓝宝石等 | 武器 | 宝石子类、属性及效果组 |
| 羊毛豆 | 羊毛；布料是否可加工另配 | 帽子、上衣、裤装 | 固定羊毛预算；如有子类则仍限羊毛 |
| 石豆 | 石头及明确指定的石材 | 雕像 | 雕像用途、尺寸与模板 |
| 木头豆 | 木材；硬木可另设子类 | 木制摆件、木椅、木桌等 | 木家具用途、材质子类 |
| 装饰豆（建议补充） | 明确支持的其他原料 | 平面拼豆画 | 无其他用途，不能作为万能填料 |

补充装饰豆是为了让其他原料仍能参与加工和颜色探索。未配置原料不自动变成金属、羊毛或其他主体材料。

材质配置使用稳定 MaterialId、AllowedUses、重量、硬度和可选效果；模板声明 ProductUse。雕像、木家具、拼豆画即使底层都是 Furniture，也按不同 ProductUse 检查。各入口共用一份用途规则，每颗豆在数量中只计一次。

建议首版：

- 武器允许合法铱／金属／宝石材质单用或混用，包括纯宝石武器，不添加金属必须占多数的要求。
- 服装、雕像、木家具严格使用对应材质，暂不开放异材质装饰豁免。
- 不兼容用料允许保留在草稿中，制造时整次拒绝；不能忽略错误豆子再重新计算比例。
- 硬度高、颜色相似或数量足够都不能替代用途许可。
- 豆子按材质存放，颜色在编辑时使用，不为每种材质和颜色组合制造一个背包堆叠。

### 首版范围

- PC 单人版，以本机实际游戏和 SMAPI 引用版本为准；多人列为 E01 扩展。
- 同一存档所有拼豆台共用图纸与颜色进度，台子只是入口。不同存档隔离。
- 原料与豆子只从当前玩家背包读取；暂不扫描附近箱子、不加入跨地图仓储。
- 中文界面，所有玩家可见文字走 i18n；不在清理或重构时改成英文。
- 优先一个 C#／SMAPI Mod；已有合理 Content Patcher 结构可以保留，避免重复维护相同数据。
- 正式素材缺少时使用明确标记的调试占位，先完成代码与布局；不把占位图当正式美术。
- 编辑、图纸保存、参考导入不扣料。加工与熨烫才改变库存。
- 熨烫一次生成一件，成功后保留当前设计并刷新用料状态。
- 首版不提供原物品免费重塑或回收成原料。读取自制成品时，从快照建立新草稿；旧成品保留，制作新版重新完整扣料。
- 建议初期豆子与自制成品使用明确的零售价规则，检查实际售卖路径不继承模板高价。出售赚钱玩法后续单独设计，不自动套用来源物品售价。
- 不增加耐久、图案识别、相邻豆子增益、在线图纸库、市场和其他无关系统。

## 数据与制作规则

### 持久化

| 数据 | 保存内容 | 约束 |
| --- | --- | --- |
| 存档进度 | 版本、已解锁颜色、首次加工记录 | 当前存档内，成功加工后更新 |
| 图纸 | 稳定 ID、名称、修订号、用途、模板、各视图、材质网格或羊毛方案、可选原图快照 | 名称不是 ID；允许同名；复制不共享可变数据 |
| 成品快照 | 制作时图案／实际颜色、版型信息、真实配料、最终属性、规则版本 | 不依赖可被删除或修改的图纸 |
| 运行时缓存 | 缩略图、纹理、解析后的参考素材 | 可删除重建，不是唯一存储 |

图纸保存更新当前会话，随正常游戏存档落盘；未存档退出按游戏规则回滚。台子移动、敲掉或重做不影响已保存图纸。SMAPI 存档 API 和实体 modData 可承载相应数据，但 modData 本身不自动阻止不同数据的物品合堆，需自行处理。[SMAPI Data 文档](https://stardewvalleywiki.com/Modding:Modder_Guide/APIs/Data)

优先用稳定物品模板承载独立快照，只处理本 Mod 标记的成品。若需动态定义，先在代码层确定加载来源、注册时机和稳定身份，不依赖运行时随机 ID 或仅在 SaveLoaded 后临时补注册。具体游戏加载效果由作者实测。

快照只存可序列化数据；不存 GPU 纹理或游戏对象引用。不同成品不得因合堆、拷贝或共用可变纹理而互相覆盖。首版自制成品可不堆叠，豆子则按实际材质身份正确堆叠。

旧图纸打开时重新计算当前的缺色、缺料和材质不兼容状态，这些实时状态不作为永久“损坏”标记。规则更新默认不改变旧成品快照。未知色卡／材质和单项损坏数据保留原内容并标记待处理，不能清空全部图纸或偷偷改成白色。

### 颜色与原料

- 原料匹配以稳定 ID 为主，支持明确的类别规则；颜色标签只决定取色，不决定材质。
- 矿石和锭分别配置产量，不能默认相同。加工预览明确区分“投入几个原料”和“得到几颗豆子”。
- 普通、银星、金星等品质默认共用解锁身份；同 ID 不同来源／颜色实例另行定义识别规则。
- 预设基础色直接可用；其他色卡都要配置至少一种支持的来源。代码检查来源映射是否完整，实际可获取性由作者试玩核对。
- 首次原料记录和已解锁色卡分开。新原料对应已解锁色时正常产豆，并显示“该颜色已解锁”。
- 没有颜色的支持原料可正常产豆，不凭空解锁新色。缺失／移除的色卡保留参考色值，标记待替换。
- 导入近似色匹配只产生色板内的颜色，不创建永远无法获取的新色卡。

### 图纸与参考导入

图纸支持新建、保存、另存、复制、改名、删除。保存和制作是独立操作：熨烫当前未保存草稿可以允许，但不自动覆盖已保存图纸；只有点“保存图纸”才更新图纸库。

删除图纸只影响图纸库。删除需要游戏内确认；关闭有未保存内容时提供“保存草稿／放弃修改／继续编辑”。切换工作台页签保留草稿和撤销历史。

打开另一张图纸、新建或复制后转入编辑，也使用同一套未保存保护。选择保存并成功后再执行原操作；保存失败或选择继续编辑则保留原草稿。单击卡片预览和切页不触发替换草稿。

读取物品时锁定所选实例的参考快照，不只保存背包槽号再在确认时重读。参考物品不移出背包、不消耗。读取自制成品优先使用其自身快照；读取普通物品使用当前内容管线的正确纹理与源矩形。[物品元数据文档](https://stardewvalleywiki.com/Modding:Items#Work_with_item_metadata)、[Content API](https://stardewvalleywiki.com/Modding:Modder_Guide/APIs/Content)

- 保留透明背景、像素比例与定位，不统一硬切成 16×16。
- 先预览原图和转换图；尺寸过大时选择裁剪、允许的大画布或最近邻缩放，不静默拉伸。
- 半透明按统一阈值转为空格或实心格；预览、计数和生成使用同一份有效格。
- 保存原参考像素，编辑图映射到完整色板。未解锁色可画草稿，制造时检查。
- 提供“换成已解锁近似色”的预览，不反复破坏原参考图。
- 导入网格先待选材质，再由玩家一键填入用途允许的材质；填入草稿不等于获得库存。
- 更换用途先预览，保留图案，把不兼容配料标为待替换，不自动兑换材料。
- 单图转服装只放入选定视图，其余视图按模板完成，羊毛预算单独计算。
- 源物品 ID 仅作来源记录，旧图纸不随来源 Mod 换图而变化。
- 导入不带来源物品的伤害、售价、附魔或功能。动画首版只取静态帧，复杂实例换肤分阶段适配。

### 计费与提交

| 成品 | 计费方式 |
| --- | --- |
| 石豆雕像 | 计费画布每个有效格一颗石豆 |
| 木头豆家具 | 计费画布每个有效格一颗允许的木头豆 |
| 平面拼豆画 | 每个有效格一颗装饰豆 |
| 武器 | 合法铱／金属／宝石网格用料，加明确补充的同类合法底料，满足模板最低量 |
| 羊毛服装 | 模板固定羊毛预算；方向和动画视图不重复收费 |

显示像素、豆子孔洞或放大倍率不改变逻辑豆数。纯显示的其他视图不重复计费；颜色条件检查所有实际使用视图。服装只画图案与颜色，面板显示“羊毛豆 × N”，不开放逐格金属／石／木配料。

空图纸可以保存；制造须满足模板规定的有效图案、视图完整性和最低用料。模板明确画布尺寸、可编辑区域及尺寸上限，不能因计算出零成本就生成空白成品。家具占地和交互锚点由模板配置，画布像素不会自动扩大碰撞或武器攻击范围。

预览、校验、扣料和快照共用同一个计费入口。真实清单逐项检查用途，底料也不例外。木、石、羊毛或装饰豆不能充当武器底料。

加工或熨烫：冻结本次输入与规则版本，检查内容、颜色、用途、库存、输出空间，再统一扣料并交付。只有加工成功才记录首次加工与色卡。容量检查考虑本次扣料释放的格子；失败不扣料，不多发或掉落代替交付。

提交中禁止重复处理同一请求。交易结束后刷新库存；每次新制作重新检查，不能复用过期的“材料足够”结论。撤销只影响设计，不撤销加工或已经完成的制造。

### 武器计算顺序

1. 验证全部真实用料与最低投入，计算材料平均硬度、平均重量指数和各类特殊豆比例。
2. 按武器模板得到基础伤害、速度、击退等。
3. 应用玩家选择且达到阈值的常驻特殊加成。
4. 在加成后应用最终上下限，保存最终数值和规则版本。
5. 命中触发效果在战斗时单独处理概率、强度和冷却，不把已计入面板的常驻加成再次叠加。

比例分母为全部真实扣除的合法豆子，含底料；每颗只计一次。不同宝石分别统计，只有配置明确共享效果组才合并。首版建议最多两种效果生效，由玩家从满足条件的效果中选择。装备、换场景和读档不能重复累加已保存属性。

计算口径为 N = Σnᵢ、平均硬度 = Σ(nᵢ × hᵢ) / N、平均重量指数 = Σ(nᵢ × wᵢ) / N、效果比例 = 对应效果组豆数 / N。N 为零时先拒绝制造。T08 将各武器模板的属性换算系数、单位和上下限集中配置，预览与成品共用同一函数；重量指数不直接等同于豆子总数。

原版已有武器伤害、速度、击退、暴击等字段；材质硬度与重量换算是本 Mod 的自定义规则。[武器文档](https://stardewvalleywiki.com/Modding:Weapons#Stats)

| 顶部 | 图纸名、草稿状态、目标用途／模板、画布尺寸、服装方向 | 切模板先预览，不静默裁图或沿用错误材料 |
| 左侧 | 画笔、橡皮、吸管、填充、撤销／重做、镜像；色板 | 默认显示已解锁色，可切“全部”查看锁定色 |

| 右侧 | 合法材质选择、库存与用量、成品预览 | 武器显示底料、比例、预计属性和特效；服装只显示羊毛预算 |
| 底部固定区 | 缺项摘要、保存图纸、熨烫制作 | 保存和扣料动作视觉上清楚区分；主按钮始终可见 |

不把“硬度”“重量”强塞给所有类别。雕像、家具和服装显示与当前制作有关的信息；武器才展开战斗属性。正式边框、底板和工具图标由作者绘制，Codex 负责区域布局、数据绑定和命中范围。

### 拼图时的操作语义

- 先选当前颜色与默认合法材质。画笔在空格放入二者；覆盖已有豆子时默认只换颜色，保留原材质。
- 填充按四方向连通：已有同色豆区域只改颜色，逐格保留材质；空白区域填入当前颜色与默认合法材质。
- 镜像提供整图水平／垂直翻转，颜色、材质与透明状态一起移动，保持配料数量和比例。
- 橡皮或画布内右键擦除整颗豆，颜色与材质一起清空。右键不能继续传给游戏背包。
- 吸管默认只取颜色。另设“换材质”工具，仅替换已有豆的材质，不改颜色，不在空格生豆。
- 提供全图 A 色换 B 色、A 材质换 B 材质。材质 B 必须符合用途，先预览，整个替换可撤销。
- 一次拖笔、一次填充、一次镜像或一次导入各算一步撤销。鼠标松开或离开有效画布后正确结束笔划，不连接出意外长线。
- 提供材质叠加查看，用标记／纹理区分同色不同材质；艺术配色仍单独保留。
- 服装隐藏逐格换材质工具，保留多方向、颜色与版型操作。
- Ctrl+Z／Ctrl+Y 用于撤销／重做；图纸名、搜索和加工数量等文本框获得焦点时，文字输入优先，不触发画布快捷键或空格平移。弹窗打开时只响应最上层弹窗。
- 滚轮在画布内缩放，在列表内滚动该列表；中键或空格拖动画布平移，提供一键居中。文字和按钮大小不跟随画布缩放。
- 绘图必须从画布内按下鼠标开始；按住按钮拖入画布不能落豆。离开画布结束笔划后，重新进入须再次按下才继续绘制。
- 画布装饰层可显示豆子外观，成品小预览显示最终图像；两者共用同一逻辑网格。

### 加工页面

从背包选择原料，输入／增减加工数量，显示产出豆数、材质用途与本次色卡状态，下方确认加工。选择只读，确认前不移走原料。

数量限制为当前可处理库存；输入非法数字或库存改变时重新校验。任务专用品等不支持项显示具体原因。加工后留在当前页，更新库存和解锁状态。

### 图纸库与导入窗口

图纸库顶部按名称搜索、按用途筛选，中央显示缩略图。选中后查看预览与“编辑／复制／改名／删除”，单击卡片不直接覆盖当前草稿。空库提供新建与读取原型入口；保存后选中对应图纸。

图纸卡片的缺色、缺料、待选材质和不兼容状态用图标加文字，不能只靠颜色。问题状态实时计算；选中问题时定位网格或配料项。

导入窗口同时显示原图和转换图，并显示目标模板、尺寸、透明处理、缺色数量和已选配料对应的用量。未选材质时显示待配料，不伪造完整费用。所有调整只改临时预览，确认后作为一次可撤销操作应用；取消不改变当前画布。

### 保存、制造与界面状态

- 缺色、缺料或配料不兼容仍可保存草稿；结构损坏或超出尺寸上限时给出具体错误。
- 无法制造时禁用熨烫按钮，并在旁边持续显示原因；点击问题可查看详情，不只在悬停时说明。
- 熨烫成功给简短反馈，保留设计，刷新材料与属性预览；不自动覆盖保存图纸。
- 保存提示准确说明随正常游戏存档保留，避免让玩家误以为可以退出而不存游戏。
- 工作台页签切换不丢草稿或撤销历史。关闭未保存内容时给出保存／放弃／继续编辑。
- 本版单人工作台菜单打开期间暂停游戏时间；关闭后恢复进入前的相关状态，不无条件覆盖其他已有暂停。页签、弹窗切换保持一致，效果由作者实测。
- 代码正确消费菜单输入，避免绘图、输入名字或点击按钮时同时触发游戏动作。

### 布局适配与美术交接

画布用整数倍像素放大，缩小时仍使用最近邻；拖动和点击按同一坐标换算。常见窗口尺寸下优先保证画布与底部操作区；较窄窗口可折叠侧栏，右侧长列表局部滚动。

锁定色显示锁标和来源名称；选中色显示边框及名称；库存不足用数字和文字同时提示。暂不加入只靠颜色理解的状态。

T04a 输出 UI 区域尺寸、控件状态、资源占位与命中区域规格；T04b 编码；T04c 整合输入、缺项和关闭流程。作者按这份规格绘制正式素材，T12 主要做替换与一致性检查。

Codex 可离线检查布局矩形、坐标换算、控件状态机和资源规格，不进行游戏内点击、截图或观感验收。实际文字截断、缩放手感、豆子可读性与美术效果由作者反馈。

## T00 — 工程与环境

**Codex 实施：** 检查现有项目及未提交修改，读取本机游戏／SMAPI 引用与 .NET 版本；区分游戏版本和 SMAPI 版本。建立或沿用最小工程、manifest、i18n 和 PROGRESS.md，确认编译输出。只读依赖元数据，不启动游戏，不复制／编辑作者存档。

**代码检查：** 构建；manifest 与依赖解析；输出路径和唯一 ID。缺少真实引用时写清缺项，不用虚构版本代替。

**作者实测：** 自行安装该构建并启动游戏，确认 SMAPI 识别 Mod；反馈启动日志。

## T01 — 独立数据与成品基础

**Codex 实施：** 建立存档、图纸、网格、材质和快照模型；实现两件不同图案成品的构造与必要绘制入口，并提供一个最小可穿戴样例代码。采用稳定身份、独立深复制、正确合堆策略和可重建缓存，返回标题时释放当前会话数据。

**代码检查：** 图纸／快照序列化往返、复制后修改互不影响、缓存键、模板引用及资源释放；核对背包／摆放／穿戴绘制入口的签名。纯数据结果不冒充 GPU 或存档集成结果，未能静态确定的运行时风险列出来。

**作者实测：**
1. 同时放置／持有两件样例，确认外观独立。
2. 放箱子、取回、正常保存重进，确认数据保留。
3. 穿戴样例并换存档，检查显示与隔离。

## T02 — 罗宾配方与工作台

**Codex 实施：** 注册拼豆台、制作配方和罗宾商品，支持放置、交互、取回；菜单采用加工／拼图／我的图纸三页，同存档台子访问相同数据。提供设备和菜单素材尺寸表，熨斗可先作为菜单制作动作与图标。

**代码检查：** ID 与配方引用、已学习处理、数据注入不覆盖其他 Mod、资源路径、已加载存档防护和各菜单入口。

**作者实测：**
1. 买配方、学配方、造台子并打开菜单。
2. 放两台，检查访问同一图纸库。
3. 搬动或重做台子，检查数据仍保留。

## T03 — 加工、材质和色板

**Codex 实施：** 配置六类主体材质及装饰豆，保留金属／宝石子类；实现统一用途规则、原料匹配、产量、加工预览和提交。颜色解锁与首次加工记录分开，未知原料不给任意用途。配置显式售价规则，避免继承测试模板高价。

**代码检查：** 原料 ID／材质／用途／色卡引用、矿石与锭产量差异、重复加工、输出空间、堆叠身份、色卡来源覆盖；使用最少样例覆盖合法／不兼容用途与失败无副作用。

**作者实测：**
1. 各加工一种木、石、羊毛、金属、铱、宝石，核对产量与用途。
2. 重复加工及加工已有颜色的新原料，核对解锁提示和产出。
3. 缺料、背包满及出售相关入口，确认不会吞料、生成额外物品或继承高价。

## T04 — 拼豆台 UI 与编辑器

本阶段分 T04a、T04b、T04c，可分别作为一次 Codex 任务执行。

**T04a 布局规格：** 按 UI 专章确定三页结构、拼图布局、导入弹窗、控件状态和美术资源清单。不要只交付按钮清单；需明确默认状态、窄窗口行为、名称输入、关闭和缺项反馈。

**T04b 核心编辑：** 实现画布、画笔、擦除、取色、填充、撤销／重做、镜像、颜色替换、材质替换、缩放、平移、参考图和实际成品预览。重涂已有豆默认只换颜色，材质工具只作用于已有豆。

**T04c 状态与输入：** 接入用途筛选、需要／拥有／缺少、武器面板接口、羊毛预算模式、弹窗优先级、未保存处理、页签保留草稿和单人暂停状态管理。后续类别还未实现时仅保留接口，不显示假的最终数值。

**代码检查：** 坐标换算和边界、批量操作一次撤销、深复制、模式切换、隐藏工具不会残留响应、输入焦点、布局范围、颜色与材质互不误改。仅测试重要逻辑，不为每个按钮写实现复刻测试。

**作者实测：**
1. 手绘一张多色图，换材质后重新涂色，检查材质仍保留。
2. 拖笔、撤销、填充、缩放和平移，检查操作与按钮命中。
3. 切页、输入名称、弹窗、关闭及窗口缩放，检查草稿和暂停状态。

## T05 — 图纸库

**Codex 实施：** 缩略图、搜索／用途筛选、选择后编辑、新建／保存／另存／复制／改名／删除。图纸 ID 与名称分离；打开用编辑副本，保存才覆盖。缺色、缺料、未选材质和不兼容分别显示，允许未完成草稿。

**代码检查：** ID 唯一性、同名处理、深复制、序列化、版本更新、删除不影响成品快照、状态实时计算、错误单项隔离。切模板保留参考并重新检查材质，不自动转换库存。

**作者实测：**
1. 保存 A、复制 B 并修改，确认 A 保持原样。
2. 改名／删除图纸，确认旧成品不变。
3. 保存重进，检查图纸、各状态与多台访问。

## T06 — 普通 sprite 导入

**Codex 实施：** 以选中实例建立临时参考快照，经当前内容管线取得纹理及正确源矩形。支持普通静态原版和标准新增物品；预览原图／转换图，处理透明、裁剪、最近邻、色板和待选材质。取消不改草稿，确认是一次可撤销应用。

**代码检查：** API 签名、纹理／源矩形边界检查、像素数组裁剪与透明处理、合法色板映射、快照隔离、取消／确认状态。没有真实游戏纹理样本时仅检查接口和纯像素逻辑，不能声称已验证目标 Mod 图像。

**作者实测：**
1. 导入原版物品和一个已有鱼类 Mod 物品，检查完整外形。
2. 预览转色／改尺寸后取消或确认，检查草稿与源物品不受误改。
3. 相同图案改成雕像、木摆件或武器，确认重新要求合法配料。

## T07 — 熨烫与首批成品

**Codex 实施：** 将冻结设计接到统一用途校验、计费和库存提交；一次生成一件带快照成品。实现木制摆件、石豆雕像及装饰豆拼豆画，占地由模板决定。熨烫保留草稿，不自动保存或覆盖图纸。

**代码检查：** 材质清单逐项检查、空图与模板尺寸边界、有效格与成本一致、输出空间含释放格、重复提交与异常回退、成功后刷新库存、售价／功能不继承源物品；对关键交易逻辑做小范围离线验证。

**作者实测：**
1. 从加工到手绘／导入、保存图纸、制造、摆放走完一次。
2. 缺一颗豆、错误材质、背包满和快速点击，核对实际消耗。
3. 同时摆放不同成品，修改／删除图纸并保存重进，检查独立性。

## T08 — 武器材质属性

**Codex 实施：** 接入剑、匕首、锤模板和输出绘制；合法铱／金属／宝石配料可单用或混用，底料也须合法。统一平均属性、最低用料、基础动作与范围、最终上下限。颜色和图案大小不直接带来无限伤害。

**代码检查：** 纯金属、纯铱、纯宝石、混合、零有效格、最少投入、不兼容底料、数值边界。预览与制造共用计算函数，结果持久化；不修改原版武器。

**作者实测：**
1. 同图案用两种合法配料制作，查看与试用不同属性。
2. 使用剑、匕首、锤，检查持握位置、挥动和命中。
3. 保存重进并切换武器，检查数值没有重复叠加。

## T09 — 特殊豆效果

**Codex 实施：** 从合法武器材料配置首批常驻加成、命中状态、带冷却触发；分别定义阈值、上限与效果组。按“基础计算—常驻加成—最终截断—保存”结算；命中效果独立，明确多帧与多目标的触发单位。

锻造／附魔的首版规则需明确配置与实现；未接入的入口限制本 Mod 武器使用，不让其他代码静默覆盖属性。作者实测相关兼容行为。

**代码检查：** 阈值前／正好／超上限、分母含合法底料、每颗一次、效果选择、冷却、加载不重叠加、一次攻击不因重复事件重复生效。不要用伪战斗模拟器代替实际触发验证。

**作者实测：**
1. 不同比例制作并试用，比较预览与效果。
2. 单目标、多目标、连续挥动、换武器，检查触发与冷却。
3. 核对已开放或已限制的锻造／附魔行为。

## T10 — 羊毛服装

本阶段分 T10a 帽子、T10b 上衣、T10c 裤装。Codex 逐段实现版型、各方向／动作映射、染色与必要袖部处理，并接入穿戴预览与快照；作者逐段实际穿戴反馈。

帽子、上衣、裤装须各自适配，单个背包图标不等于完整穿着素材。[帽子](https://stardewvalleywiki.com/Modding:Hats)、[上衣](https://stardewvalleywiki.com/Modding:Shirts)、[裤装](https://stardewvalleywiki.com/Modding:Pants)

**代码检查：** 视图索引与资源布局、版型边界、羊毛固定预算、禁止异材质补足、视图不重复计费、各成品快照独立。方向与动画是否自然只能由作者实测。

**作者实测：**
1. 制作并穿戴两件不同作品，检查不会串图。
2. 站立、走路、挥工具和各朝向，检查对齐与缺层。
3. 换装、存衣柜／箱子、保存重进，检查外观与用料。

## T11 — 复杂导入与功能家具

**Codex 实施：** 给支持的实例染色和多层绘制增加适配，缓存键包含相关实例状态，动画定格。读大家具时采用实际贴图尺寸和方向，服装参考与可穿输出继续分开；导入不含数量、品质星和选中框。

如采用离屏渲染，核对调用阶段和状态恢复，暂不能靠离线检查证明 GPU 路径正确。为木椅／木桌实现座位、放物点和遮挡，仍限定木豆；石雕像不继承椅子或其他来源的功能。

**代码检查：** 类型适配分支、纹理边界、实例缓存、失效处理、资源释放、来源快照与图纸解耦；建立支持表，分别记录“代码实现范围”和“作者实测结果”。

**作者实测：**
1. 同 ID 不同染色、大家具、动画定格，核对导入结果。
2. 木椅坐下、木桌放物，检查交互和遮挡。
3. 更换来源贴图／Mod，检查旧图纸与成品保持原样，新导入正确更新。

## T12 — 美术整合与代码回归

**Codex 实施：** 接入作者正式素材，检查布局规格与 i18n；处理缓存、会话清理、旧版本迁移、单项损坏与未知引用。保留旧数据备份策略，不操作作者真实存档来试验。多人未实现时明确版本边界。

按本次变更选相关构建、配置、纯逻辑和资源检查；不重复全套已有测试。收集作者反馈，修复后只将受影响的实测项重置为 NOT_RUN。

**代码检查：** 素材尺寸／引用、可恢复数据结构、迁移样例、用料／用途关键回归、无重复每帧加载、版本与发布配置。不要用占位美术声明正式 UI 完成。

**作者集中实测：**
1. UI 观感、常用缩放、所有页面与暂停恢复。
2. 加工／拼图／导入／图纸／制造，以及背包与错误材料边界。
3. 保存重进、换存档、更新 Mod 和关键成品行为。

## T13 — 测试版安装包

**代码检查：** Release 构建、解压安装包离线检查目录／依赖／资源／配置，确认不依赖开发目录临时文件。Codex 不启动游戏执行安装验证。

**作者实测：**
